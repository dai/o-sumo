# o-sumo Public API v1

o-sumo は静的 JSON を配信します。現在の公開エンドポイントは以下です。

- `GET /api/v1/banzuke.json`
- `GET /api/v1/torikumi.json`
- `GET /api/v1/rikishi.json`
- `GET /api/v1/rikishi/{id}.json`
- `GET /api/v1/rikishi-matchups.json`
- `GET /api/v1/gyoji.json`
- `GET /api/v1/gyoji/{id}.json`
- `GET /api/v1/yobidashi.json`
- `GET /api/v1/yobidashi/{id}.json`

ベース URL 例: `https://osada.us`

## 共通仕様

- 形式: `application/json; charset=utf-8`
- 更新: GitHub Actions により定期更新（詳細は `docs/api/policy.md`）
- 文字列: 日本語を含む UTF-8
- 日付: `isoDate` は `YYYY-MM-DD`、`updatedAt` は生成時刻文字列

番付・取組エンドポイント共通頂レベル項目:

- `bashoName`: 例 `"七月場所"`
- `year`: 例 `"令和八年"`
- `updatedAt`: 最終生成日（JST基準の日付文字列）。取組レスポンスでは `resultUpdatedAt` と `scheduleUpdatedAt` のうち新しい方と一致
- `resultUpdatedAt`: 結果アーカイブの更新日（JST基準）。`torikumi.json` のみ
- `scheduleUpdatedAt`: 予定アーカイブの更新日（JST基準）。`torikumi.json` のみ
- `source`: 値の由来。`"banzuke.json"` の `updatedAt` は `torikumi.json` の `resultUpdatedAt` を引き継ぐ

七月場所は確定済みです。九月場所の番付が公式公開されるまでは、`banzuke.json` と `torikumi.json` はともに七月場所 (`202607`) のcurrent dataを返します。`resultDays` / `scheduleDays` は `torikumi.json` 専用の15日アーカイブ項目であり、七月の不変スナップショットは月別HTMLルートを支えます。月別JSON endpoint や新しいAPI schemaは追加しません。

### 更新日時の責務分離

生成器・画面・Markdown・CI の間で次に示す責務分離を保ち、各フィールドは独立に更新されます。CI でも `updatedAt === max(resultUpdatedAt, scheduleUpdatedAt)` と `banzuke.updatedAt === torikumi.resultUpdatedAt` を値まで検証します。

- 番付 (`banzuke.json`): 結果更新と同一の `updatedAt`（= `torikumi.json.resultUpdatedAt`）。予定のみの更新では進まない
- 結果 (`torikumi.json.resultDays` / 取組結果 hub・day): `resultUpdatedAt`
- 予定 (`torikumi.json.scheduleDays` / 取組予定 hub・day): `scheduleUpdatedAt`
- 過去場所 (`/202603/`, `/202605/`, `/202607/`): 月別 snapshot 内の `BanzukeData.updatedAt` / `TorikumiData.updatedAt`
- 力士 index / detail (`rikishi.json`, `rikishi/{id}.json`): 各 JSON の `updatedAt`（detail にあれば detail を優先し、なければ index の値）
- 力士合い口 (`rikishi-matchups.json`): 全対象プロフィールを検証して一括生成した時刻 `updatedAt`
- 行司・呼出 index / detail (`gyoji.json`, `gyoji/{id}.json`, `yobidashi.json`, `yobidashi/{id}.json`): 各 JSON の `retrievedAt`
- ニュース記事 (`news-feed-update.yml`): 各記事の `publishedAt`（feed 自体の `updatedAt` は画面表示に使用しない）

更新日時が存在しない静的ページ（Archives 一覧、Kimarite 一覧など）には、無関係な日時は表示しません。

## `GET /api/v1/banzuke.json`

番付データです。

### レスポンス構造

- `bashoName`: 例 `"七月場所"`
- `year`: 例 `"令和八年"`
- `updatedAt`: 結果更新と連動した日時（JST基準）。`torikumi.json.resultUpdatedAt` と同じ値
- `makuuchi`: 幕内の段配列（例: 横綱, 大関, ...）
- `juryo`: 十両の段配列

段オブジェクト:

- `title`: 段名
- `east`: 東の力士配列
- `west`: 西の力士配列

力士オブジェクト:

- `id`: 力士ID（数値）
- `name`: しこ名
- `yomi`: よみ
- `rank`: 番付
- `side`: `east` or `west`
- `wins` / `losses` / `draws`: 星数
- `results`: 日別の勝敗配列（`win` / `loss` / `draw` / `null`）。`null` は未確定または不明を表し、`wins` / `losses` / `draws` の集計対象外
- `profileUrl`: 協会プロフィール URL
- `memo`: 備考

### レスポンス例（抜粋）

```json
{
  "bashoName": "七月場所",
  "year": "令和八年",
  "updatedAt": "2026-07-26T18:44:23+09:00",
  "makuuchi": [
    {
      "title": "横綱",
      "east": [
        {
          "id": 3842,
          "name": "豊昇龍",
          "yomi": "ほうしょうりゅう",
          "rank": "横綱",
          "side": "east",
          "wins": 11,
          "losses": 4,
          "draws": 0,
          "results": ["win", "win", "win", "loss"],
          "profileUrl": "https://www.sumo.or.jp/ResultRikishiData/profile/3842/",
          "memo": ""
        }
      ],
      "west": [
        {
          "id": 4227,
          "name": "大の里",
          "yomi": "おおのさと",
          "rank": "横綱",
          "side": "west",
          "wins": 0,
          "losses": 4,
          "draws": 11,
          "results": ["loss", "loss", "loss", "loss"],
          "profileUrl": "https://www.sumo.or.jp/ResultRikishiData/profile/4227/",
          "memo": ""
        }
      ]
    }
  ]
}
```

## `GET /api/v1/torikumi.json`

取組結果・予定データです。

### レスポンス構造

- `bashoName`: 例 `"七月場所"`
- `year`: 例 `"令和八年"`
- `updatedAt`: 結果・予定・番付のうち最も新しい更新日（JST基準）。`max(resultUpdatedAt, scheduleUpdatedAt)` と一致
- `today`: 当日の結果/予定（`makuuchi`, `juryo`）
- `tomorrow`: 翌日の予定（`makuuchi`, `juryo`）
- `resultDays`: 15日分の結果アーカイブ
- `scheduleDays`: 15日分の予定アーカイブ
- `resultUpdatedAt`: 結果アーカイブの更新日
- `scheduleUpdatedAt`: 予定アーカイブの更新日

`today.makuuchi` などの division オブジェクト:

- `day`: 取組日番号（1-15）
- `dayName`: 例 `"取組日 十四日目"`
- `dayHead`: 例 `"初日： 令和8年5月10日(日)"`
- `division`: `"幕内"` / `"十両"`
- `matches`: 取組配列

`matches[]`:

- `division`
- `boutNo`
- `eastYomi` / `westYomi`
- `eastName` / `westName`
- `eastProfileUrl` / `westProfileUrl`
- `eastRank` / `westRank`
- `eastEnglish` / `westEnglish`
- `kimarite`
- `winner`（`east` / `west` / `null`）

`resultDays[]` / `scheduleDays[]` の日別オブジェクト:

- `day`, `isoDate`, `pathDate`, `label`, `dayHead`
- `status`: `published` or `pending`
- `statusMessage`: 結果なら `"結果未更新"`、予定なら `"取組予定未更新"`、公開済みなら `null`
- `data`: `{ makuuchi, juryo }`

### pending 日の扱い

未更新日の場合 `status = "pending"` になります。クライアント側では次を推奨します。

1. 対象日のページやカード自体は表示し、URLを固定化する
2. 取組表の代わりに `statusMessage` を表示する
3. 空配列を「エラー」とみなさない
4. `statusMessage` は結果なら `"結果未更新"`、予定なら `"取組予定未更新"` になる
5. `pending` 日の `matches` は空配列になる

### 履歴レスポンス例（2026年五月場所、形式のみ）

```json
{
  "bashoName": "五月場所",
  "year": "令和八年",
  "updatedAt": "2026-06-29T14:16:57+09:00",
  "resultUpdatedAt": "2026-05-25T09:59:34+09:00",
  "scheduleUpdatedAt": "2026-06-29T14:16:57+09:00",
  "resultDays": [
    {
      "day": 1,
      "isoDate": "2026-05-10",
      "pathDate": "20260510",
      "label": "初日",
      "dayHead": "初日： 令和8年5月10日(日)",
      "status": "pending",
      "statusMessage": "結果未更新",
      "data": {
        "makuuchi": {
          "day": 1,
          "dayName": "取組日 初日",
          "dayHead": "初日： 令和8年5月10日(日)",
          "division": "幕内",
          "matches": []
        },
        "juryo": {
          "day": 1,
          "dayName": "取組日 初日",
          "dayHead": "初日： 令和8年5月10日(日)",
          "division": "十両",
          "matches": []
        }
      }
    }
  ]
}
```

`pending` 日の実レスポンスでは、上記の日別オブジェクトと同じ形のまま `status` が `pending`、`statusMessage` が `"結果未更新"` または `"取組予定未更新"` になり、`matches` は空配列になります。

## `GET /api/v1/rikishi.json`

力士の基本情報一覧です。

### レスポンス構造

- `updatedAt`: 一覧の最終生成日（JST基準の日付文字列）
- `rikishi`: 力士の配列

`rikishi[]` 要素:

- `id`: 力士ID（数値）
- `name`: しこ名
- `yomi`: よみ
- `currentRank`: 現在の番付
- `profileUrl`: 協会プロフィール URL

### レスポンス例（抜粋）

```json
{
  "updatedAt": "2026-04-27",
  "rikishi": [
    {
      "id": 3842,
      "name": "豊昇龍",
      "yomi": "ほうしょうりゅう",
      "currentRank": "横綱",
      "profileUrl": "https://www.sumo.or.jp/ResultRikishiData/profile/3842/"
    }
  ]
}
```

## `GET /api/v1/rikishi/{id}.json`

指定した力士IDのプロフィール詳細です。`{id}` には `rikishi.json` の `id` を使います。

### レスポンス構造

- `id`: 力士ID（数値）
- `name`: 四股名
- `yomi`: よみ
- `currentRank`: 現在の番付
- `birthDate`: 生年月日（取得できない場合は空文字）
- `height`: 身長（cm）
- `weight`: 体重（kg）
- `shusshin`: 出身地またはプロフィール上の出身情報
- `debut`: 初土俵
- `careerStats`: 通算成績オブジェクト
  - `wins`: 勝数
  - `losses`: 敗数
  - `draws`: 休場数
- `photoUrl`: プロフィール画像URL（通常は `/images/rikishi/{id}.png`。日本相撲協会プロフィール写真をもとに MiniMax I2I Generation で加工したローカル画像を優先し、取得できない場合は空文字）
- `sourceUrl`: 協会プロフィール URL
- `updatedAt`: 個別プロフィール JSON の最終生成日（JST基準の日付文字列）

### レスポンス例（抜粋）

```json
{
  "id": 3842,
  "name": "豊昇龍",
  "yomi": "ほうしょうりゅう",
  "currentRank": "横綱",
  "birthDate": "平成11年5月22日（26歳）",
  "height": 188,
  "weight": 148,
  "shusshin": "東大関",
  "debut": "平成三十年一月場所",
  "careerStats": {
    "wins": 0,
    "losses": 0,
    "draws": 0
  },
  "photoUrl": "/images/rikishi/3842.png",
  "sourceUrl": "https://www.sumo.or.jp/ResultRikishiData/profile/3842/",
  "updatedAt": "2026-04-27"
}
```

## `GET /api/v1/rikishi-matchups.json`

現行の幕内・十両力士について、日本相撲協会プロフィールに掲載された場所・日別の取組履歴から生成した通算合い口です。改名前後の四股名は同じ公式力士IDへ統合し、休場・取組なしは勝敗に含めません。

### レスポンス構造

- `updatedAt`: 全対象プロフィールの取得・ID解決・相互整合を確認して生成したISO 8601日時
- `matchups`: 対戦履歴があるIDペアの配列
  - `rikishi1Id` / `rikishi2Id`: 公式力士ID。常に `rikishi1Id < rikishi2Id`
  - `rikishi1Wins` / `rikishi2Wins`: 各IDの勝数。0以上の整数

IDペアは一意です。対象となる2人のペアが配列にない場合、比較画面は対戦なしとして `0-0` を表示します。JSONの取得失敗、スキーマ不正、重複ペアなどの不整合がある場合は推測せず「不明」と表示します。

### レスポンス例（抜粋）

```json
{
  "updatedAt": "2026-08-17T17:24:24+09:00",
  "matchups": [
    {
      "rikishi1Id": 4230,
      "rikishi2Id": 4279,
      "rikishi1Wins": 1,
      "rikishi2Wins": 5
    }
  ]
}
```

比較画面は列順に応じてこの例を `1-5` または `5-1` と表示します。値は生成時点の公式プロフィール履歴に基づきます。

## `GET /api/v1/gyoji.json` / `GET /api/v1/yobidashi.json`

日本相撲協会公式サイトから取得した現役行司・呼出の一覧です。行司は42名、呼出は45名を収録し、写真・画像フィールドは含みません。

### レスポンス構造

- `retrievedAt`: 公式サイトから取得したUTC日時
- `source`: 公式一覧ページURL
- `officials`: プロフィール概要の配列
  - `id`: 種別内で一意な公式数値ID
  - `name` / `yomi` / `realName`: 名前、読み、本名
  - `rank` / `rankCode`: 公式の格付と機械可読コード
  - `affiliation`: 所属部屋
  - `sourceUrl`: 公式個別プロフィールURL

## `GET /api/v1/gyoji/{id}.json` / `GET /api/v1/yobidashi/{id}.json`

指定した公式数値IDの個別プロフィールです。`{id}` には対応する一覧JSONの `officials[].id` を使います。行司と呼出では同じ数値IDが存在し得るため、種別をまたいでIDを共有しません。

一覧項目に加えて次の項目を返します。

- `kind`: `gyoji` または `yobidashi`
- `birthDate`: 生年月日（`YYYY-MM-DD`）
- `birthplace`: 出身地
- `adoptedAt`: 採用年月（`YYYY-MM`）
- `retrievedAt`: 公式サイトから取得したUTC日時
- `nameHistory`: 行司名の履歴。公式ページに履歴がある場合のみ掲載
