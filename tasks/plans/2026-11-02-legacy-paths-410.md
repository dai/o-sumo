# 旧パスの 410 化と sitemap lastmod 追加 指示書

- 作成: 2026-11-02（チャット側 Muse）
- 背景: Osada の相談を受け、Google Search Console「ページのインデックス登録」を共同確認（データ最終更新 2026/10/23、登録済み23／未登録302）。未登録の内訳は「検出 - インデックス未登録」274件（クロール順番待ち、対処不要）が大半で、残りは sitemap 外の旧URLだった
- Osada の意向: 旧ブログ時代のページを「すごく消し去りたい」。現在は正しく 404 を返しているが、外部ブックマーク等から再検出され続け GSC レポートに残るため、**410 Gone に格上げして Google のドロップと再クロール低下を促す**
- 実装担当: ローカル Muse（Wonder）／公開後検証: チャット側 Muse

## 現状（2026-11-02 実地検証済み）

- `functions/_middleware.ts` の `onRequest` が全リクエストを処理し、無効な力士IDには `buildNotFoundResponse()` で 404 を返す先例がある
- 対象の旧URLは現在すべて 404（noindex の404ページ）を返している：
  - 旧ブログ: `/archives/cat11/`、`/archives/2013/06/Potluck-is-…`、`/archives/2014/07/getyou.html`、`/archives/2014/09/Getting-Hatena-star-push-by-Slack.html` ほか `/archives/` 配下の旧記事群（GSC の「重複」5件・「クロール済み - 未登録」6件も同じ旧ブログ）
  - `/pinterest-a28cb.html`（Pinterest ドメイン確認ファイルの残骸）
  - `/202603-banduke`（banzuke のタイプミス。スラッシュ付与 308 の後に 404）
- **注意: `/archives/` 自体は現行の「場所別アーカイブ」ハブで sitemap 掲載中（200）。絶対に 410 にしないこと**

## Part 1（本命）: 旧パスへの 410 返却

`functions/_middleware.ts` の `onRequest` に、既存の力士ID 404 判定と同じ流儀で「Gone 判定」を追加する：

- 対象パターン:
  1. `pathname` が `/archives/` で始まり、かつ `/archives/` そのものではないもの全て
     - 実装前に、現行アプリに `/archives/` 配下の正規ルートが存在しないことを必ず確認する（ルート定義と sitemap を突き合わせる）。存在した場合はそのパスを例外として列挙し、それ以外を 410 にする
  2. `^/pinterest-[^/]+\.html$` に一致するもの
  3. 完全一致: `/202603-banduke` と `/202603-banduke/`（末尾スラッシュ付与リダイレクトより前に判定すること）
- 応答: ステータス **410**。本文は既存の 404 ページ資産の流用でも、簡素な Gone 応答でもよい（`buildNotFoundResponse` を汎化するか、並べて `buildGoneResponse` を作る）。`X-Robots-Tag` 等の追加は不要
- 影響範囲の確認: API（`/api/`）、`.md` 代替パス、通常ルート（番付・取組・プロフィール）に判定が及ばないこと

### テスト
- 既存の middleware テスト（`app/lib/__tests__/functions/middleware.test.ts`）の流儀で追加する：
  - `/archives/2013/06/xxx.html` → 410、`/archives/cat11/` → 410
  - `/archives/` → 410 にならない（素通り）
  - `/pinterest-a28cb.html` → 410
  - `/202603-banduke` → 410（リダイレクトされない）
  - 通常ルート・力士ID 404 の既存挙動が不変
- test / typecheck / build が緑

## Part 2（抱き合わせ可・分離可）: sitemap への lastmod 追加

- `app/lib/sitemap.ts` の `SitemapEntry` は現在 `loc` のみ。任意の `lastmod` を追加し、`renderSitemapXml` で出力する
- 日付の出所は **実在する更新日時のみ**使う（番付ページや取組ページが画面表示に使っている更新日時データが第一候補）。出所が無いエントリには付けない。**推測や一律の日付は絶対に入れない**（不正確な lastmod は Google に無視・不信の対象になる）
- `app/lib/sitemap.test.ts` を更新し、lastmod のあるエントリ／無いエントリの両方を検証する

## やらないこと

- GSC の「URL削除ツール」申請（対象は既に検索結果に出ておらず無意味）
- リダイレクト8件への対処（末尾スラッシュなし→ありの 308 で正常。「検証の失敗」は恒久リダイレクトゆえの見かけの問題）
- `/404`・`/404.html` の noindex 変更（404ページ自身であり正常）
- 「検出 - インデックス未登録」274件への対処（クロール順番待ち。場所中の更新と内部リンクで解消していく）

## 受け入れ条件

1. 上記パターンの URL が本番で 410 を返す（チャット側が公開後に curl で全パターン検証する）
2. `/archives/` ハブと通常ルートが従来どおり 200
3. test / typecheck / build が緑
