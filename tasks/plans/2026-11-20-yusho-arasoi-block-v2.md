作成：2026-11-20（十二日目終了後、十三日目開始前）
対象：PR #766 で追加された日別取組結果ページの「優勝争い」ブロック
種別：既存ブロックの表示改修のみ。データ生成・公開JSON・既存ページ構成には手を入れない。
承認：2026-11-20、Osada が改修案（本指示書の 1〜4）を確認して承認済み。

## 背景・Osada の要望

初版（指示書 `tasks/plans/2026-11-17-yusho-arasoi-block.md`、PR #766 で 2026-11-19 マージ済み）は本番で動いている。そこからの改修要望は次の4点。

1. 全体的にこなれた感じにしたい。
2. 首位グループに、現在のラベルに加えてシンプルな表を入れたい。
3. 「本日の注目対戦」は、（過去日のページでは）現時点では既に昨日なので、日付で「昨日」表示に変えたい。
4. 優勝条件は日に日に明らかになってゆくので、具体的な表などで示したい。

残り日程が短い（本日・十三日目〜千秋楽）。十四日目・千秋楽に間に合えば最優先で間に合わせ、間に合わなくても今後の場所でそのまま使える形にすること。正確さを速度より優先する。

## 改修仕様

### 0. ブロック冒頭に「時点」を明記する（こなれ感の土台）

- 見出し「優勝争い」の直下または右肩に、そのブロックの集計時点を小さく表示する。
  - 例：`十二日目終了時点`（当該ページの前日終了時点の星取で組まれている場合）
  - 例：`十二日目終了時点 ・ 十三日目開始前`
- 時点の定義は既存の集計どおり（そのページが依拠する最新結果まで）。新しい集計は作らない。表示文だけを足す。
- 見出し階層・余白・罫線は、同じページの取組表・既存カードと揃える。ブロック内だけ書体や余白が浮かないようにする。

### 1. 首位グループ：ラベルは残し、シンプルな表を追加する

- 現在のラベル表示（例：`首位 若元春 11勝1敗 ／ 1差 大の里・熱海富士・金峰山 10勝2敗`）は残す。要約として先に読ませる役割。
- その直下に表を追加する。列は次の6つだけに絞る（増やさない）。

| 列 | 内容 |
|---|---|
| 差 | `首位` / `1差` / `2差` …（首位の勝ち数との差） |
| 力士 | 力士名（既存どおり力士ページへのリンクがあれば維持） |
| 成績 | 例：`11勝1敗`（休場がある場合は既存表記に合わせる） |
| 残り | その力士の残り取組数 |
| 最大 | 残り全勝した場合の最終成績（例：`14勝1敗`） |
| その日の相手 | そのページの日の対戦相手。取組がない日は `取組なし`、相手未定なら `—` |

- 並びは現行どおり：勝ち数の多い順、同数は既存の星取表の並び。
- 対象（首位グループの定義・人数）は現行の抽出条件を変えない。
- スマホ幅で横に溢れないこと。溢れる場合は列名を短くする／フォントを取組表に合わせる等の既存手段で収め、横スクロール前提にしない。
- 「その日の相手」の列見出しも日付基準にする（後述 2 と同じ考え方。当日なら `本日の相手`、過去日なら `相手` でよい。迷ったら `相手` に統一する）。

### 2. 注目対戦：見出しを「本日」固定から日付基準に変える

現行の `本日の注目対戦` は、そのページの日が過去になると嘘になる（例：十三日目に十二日目のページを開くと、十二日目の対戦が「本日」と出る）。ページの日付と閲覧日（JST）の関係で出し分ける。

| ページの日と閲覧日の関係 | 見出し |
|---|---|
| 同じ日 | `本日（M月D日・○日目）の注目対戦` |
| 閲覧日の前日 | `昨日（M月D日・○日目）の注目対戦` |
| それより過去 | `M月D日（○日目）の注目対戦` |
| 翌日 | `明日（M月D日・○日目）の注目対戦` |
| それより未来 | `M月D日（○日目）の注目対戦` |

- 相対語（本日／昨日／明日）には必ず絶対日付を併記する。相対語だけにしない。
- 判定は閲覧側の現在日（JST）で行う。静的生成時点の日付で固定しない（過去ページを後日に開いたときも正しくなるように）。既存のクライアント側日付判定があればそれを使う。
- テストでは日付を固定して上表の5パターンを検証できるようにする（システム日時に依存する書き方にしない）。

#### 終了した日の注目対戦は「結果付き」にする

- そのページの日の取組が終了している場合、注目対戦の各行に対戦結果を付ける。
  - 例：`若元春 ○ 寄り切り ― 義ノ富士` のように、勝敗（○●）と決まり手を示す。
- 終了していない（当日の開始前・進行中）場合は現行どおり対戦カードとして表示し、終わった取組だけ結果を付ける（既存データの判定に合わせる。`未定` を結果として扱わない。イマココの既存ルールと同じ）。
- これにより過去日のページが「その日の注目対戦と結果」として完結する。

### 3. 首位グループの直接対決：リストからマトリクス表へ

- 現行の「未対戦（n組）／対戦済み」の箇条書きは、内容は変えずに正方マトリクス表で示せるようにする。
  - 行・列とも首位グループの力士（首位グループ表と同じ並び）。
  - セル：対戦済みなら `○` または `●` と対戦日（例：`○ 4日目`）、未対戦なら `未`、そのページの日に組まれている未対戦は `未・本日` のように当日の対戦だと分かる表記にする（当日の判定は 2 の日付基準と揃える。過去日ページでは `未・その日` とは書かず、その日の結果側に寄せる）。
  - 自分同士のセルは `―`。
- グループが大きい（最大6人程度）場合でもスマホで収まる文字サイズ・余白にする。収まらない場合は現行リスト表示へのフォールバックを残してよい（データは同じものを使う）。

### 4. 優勝条件：短文から「条件表」へ。残りが減るほど自動で具体化する

現行の短文2行（首位／追う側まとめ）は、力士ごとの表に置き換える。まとめ文を残す場合は表の上に1行だけ置いてよいが、表が本体。

#### 表の列

| 列 | 内容 |
|---|---|
| 力士 | 力士名 |
| 現在 | 現在の成績（例：`11勝1敗`） |
| 残り | 残り取組数 |
| 全勝時 | 残り全勝した場合の最終成績（例：`14勝1敗`） |
| 優勝条件 | その力士が優勝するための条件（下記の生成規則） |
| 決定戦／脱落 | 決定戦になる条件、または可能性が消える条件 |

列が横に広いので、スマホでは「優勝条件」と「決定戦／脱落」を1列にまとめた2段表記にしてよい。列の意味は変えない。

#### 生成規則（ハードコードしない。すべて集計値から機械的に作る）

各力士 i について次を定義する。

- `W_i` = 勝ち数、`L_i` = 敗数、`R_i` = 残り取組数
- `MAX_i = W_i + R_i`（残り全勝時の勝ち数）
- 首位の勝ち数を `W_top`、首位力士を `top` とする。

条件文は次の観点で組み立てる（該当しない観点は書かない）。

1. **単独優勝が確定する到達点**
   - 力士 i が、他の全員の `MAX` を上回る勝ち数に到達すれば単独優勝確定。
   - 例（首位）：「残り全勝で14勝1敗、単独優勝確定」
   - 例：「あと2勝で他の全員の最大を上回り、その時点で単独優勝確定」のように、残りが少ない終盤では「あと○勝で確定」まで具体化する。到達不能なら書かない。
2. **同点・決定戦になる条件**
   - 力士 i の到達勝ち数と、他の力士の到達勝ち数が並ぶ場合に決定戦になることを、相手側の必要勝敗とセットで書く。
   - 例（追う側）：「全勝（13勝2敗）が前提。若元春があと2敗で同点決定戦、3敗で単独逆転」
   - 例（首位）：「13勝2敗なら、2敗勢の全勝（13勝2敗）と決定戦」
3. **前提条件**
   - 追う側は原則として「残り全勝が前提」かどうかを明記する。全勝しなくても可能性が残る場合は、その最低ライン（例：`あと2勝1敗でも、首位が…なら決定戦圏内`）を書く。計算で出せる範囲に限る。
4. **脱落条件**
   - `MAX_i < W_top` になった力士は優勝可能性なし（そもそも首位グループ抽出から外れる想定だが、条件表側でも矛盾させない）。
   - `MAX_i == W_top` の力士は「決定戦のみ（単独優勝はなし）」と明記する。
   - 残りが減るにつれ、上記 1〜3 は自動的に狭まる。これが「日に日に明らかになる」の実装上の意味であり、特別な日別分岐は作らない。

#### 直接対決がある日の追加行（残り3日以下）

- そのページの日に首位グループ同士の直接対決がある場合、条件表の下に1行だけ追加してよい。
  - 例：`本日の直接対決：若元春が勝てば12勝1敗で、大の里は10勝3敗となり単独優勝は消える（決定戦のみ）。大の里が勝てば両者11勝2敗で並ぶ。`
- 勝敗それぞれの場合の、両者の成績と首位関係だけを書く。予測・感想は書かない。
- 相対語を使う場合は 2 の日付基準に従う（過去日ページでは結果で確定しているので、この行は結果文に置き換わる／出さない）。

#### 文面の原則

- 予測・確率・感想は書かない。計算で確定できる条件だけを書く（初版の原則を維持）。
- 条件が複雑で1セルに収まらない場合は、最も到達可能性の高い分岐（全勝時と、あと1敗時）までに絞る。全分岐の列挙はしない。
