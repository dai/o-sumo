# 設計: 「イマココ」メーター（只今の取組ボードへの統合）

作成日: 2026-10-27 JST（v3: カードデザインのオーナー指示を反映）
対象: dai/o-sumo、ホームの「只今の取組」ボード（既存 Quick Nav カードの拡張）
関連: `tasks/plans/2026-09-18-torikumi-ux-design.md`（手動更新・スクロール保持の設計）
参考: 日本相撲協会 十一月場所スケジュール
https://www.sumo.or.jp/Watching/guide/Nov/schedule/638/
（時刻の目安の参照元として使う。協会ページの縦書きレイアウトは採用しない）

## 1. Task

取組が発表されたらホーム最上部に出る「只今の取組」ボードに、一日の流れの
中の現在位置を示す簡易タイムライン「イマココ」メーターを組み込む。

```text
┌────────────────────────────────────┐
│  只今の取組            16:20 現在   │
│  東 A 対 西 B                      │
├────────────────────────────────────┤
│  14:00    14:15      15:45   18:00 │  ← 時刻列はメーター最上段
│  幕下取組中│ 十両      │ **幕内**   │  ← 現在の部は太字
│  █░███████│███████████│░░░░░░░░░  │  ← セグメント間にボーダー
│              ↑ イマココ（A 対 B）   │
└────────────────────────────────────┘
```

狙いは速報ユーザーの「いま一日の中でどのあたりか」「推しの取組まで
あとどれくらいか」に1秒で答えること。ボード単体（現在の一番）だけでは
前後関係が見えないため、メーターをボードの下段に結合する（別設置にしない）。

## 2. Context（調査結果: 既存ロジック）

- ホーム hero の Quick Nav カードとして「ただいまの取組」導線は実装済み。
  `app/components/LiveTorikumiCardLink.tsx` がクリック時に
  `buildLiveTorikumiTarget(archive, data)`（`app/page.tsx`）を再計算し、
  当日結果ページの現在位置アンカー（`#bout-juryo-{n}` /
  `#bout-makuuchi-{n}`）へ遷移する。PR #639 の ScrollToHash が着地を担う。
- 現在位置の推定は **実績ベースではなく時刻ベース**（`app/page.tsx`）:
  `LIVE_START_MINUTES = 13:00`、`MAKUUCHI_START_MINUTES = 15:30`、
  `LIVE_END_MINUTES = 18:00` の窓を `boutNumberForWindow()` が経過時間で
  線形按分し、`nearestTorikumiAnchor()` が現在の一番を推定する。
- 当日データ `TorikumiDailyData` が持つのは **十両と幕内のみ**。
  幕下以下の取組データはサイトに存在しない。
- 結果の反映経路: リアルタイム更新ワークフローが JST 15:00–17:57 に
  3分間隔で結果を push（`realtime-torikumi-direct-update.yml`）。
  幕内については「確定済みの番数」がデータから数えられる。

## 3. オーナー判断（2026-10-27、確定事項）

1. **タイムラインは 14:00 開始 〜 18:00 終了**。左端に幕下帯が少しだけ入る。
2. **モバイルではピンラベルの四股名を省略**し（既定案通り）、代わりに
   **ボードの一番上に現在時刻を表示**する。
3. **十両開始より左は「幕下取組中」として一括り**にする。
   細分化しない・四股名も出さない。
4. レイアウトは **横書きのみ** とし、縦書きは使わない。
5. カードの見た目（2026-10-27 追加指示）:
   - 境界時刻の列はメーターの **一番下ではなく一番上** に置く。
   - ラベル列は「幕下取組中」を **小さく・グレイ** 表示とし、
     十両・幕内は通常サイズ。**イマココに該当する部（十両か幕内）は太字**。
   - セグメントの **間にボーダー** を入れる。
   - 幕下取組中はあくまで「始まりの目安」の位置づけで、
     **主役は十両・幕内** とする。

## 4. Decisions

### D-1: 配置はボード内蔵（ホーム最上部ボードの下段）

- メーターは「只今の取組」ボードの下段に置く。独立コンポーネントとして
  作るが、表示は常にボードと一体。ボード自体の表示条件（取組発表済み・
  場所中などの既存の出し分け）は変更しない。
- 日別結果ページのヘッダーへの転用は Phase 2 とし、本設計では扱わない
  （2026-09-18 設計の手動更新ボタンと干渉させない）。

### D-2: タイムラインの定数（14:00–18:00）

表示専用の定数として `app/lib/live-progress.ts` に置く。
既存のアンカー推定窓（13:00 / 15:30 / 18:00）とは別管理とし、
混同しないよう命名を分ける。

| 定数 | 値 | 意味 |
|---|---|---|
| `METER_START_MINUTES` | 14:00 | タイムライン左端 |
| `METER_JURYO_START_MINUTES` | 14:15 目安 | 十両の開始（幕下帯の右端） |
| `METER_MAKUUCHI_START_MINUTES` | 15:45 目安 | 幕内の開始（土俵入り目安） |
| `METER_END_MINUTES` | 18:00 | 右端（打ち出し目安） |

- 14:15 / 15:45 は目安であり、実装前に協会公式スケジュール
  （十一月場所のページ、上記リンク）で当場所の値を最終確認して定数に落とす。
  場所ごとに変わりうるため、定数は「目安」として一箇所に集約する。
- セグメント幅はこの時刻配分に比例させる:
  幕下帯 = 14:00–14:15（全体の約6%、細い帯）、
  十両 = 14:15–15:45（約38%）、幕内 = 15:45–18:00（約56%）。

### D-3: メーターの構造と進捗

- セグメントは左から **幕下取組中｜十両｜幕内** の3つ。すべて横書き。
- 「幕下取組中」はセグメントというより **状態バンド** として扱う:
  十両開始前はこの帯だけが意味を持ち、ピンラベルも
  「イマココ（幕下取組中）」とする。四股名・番数は出さない。
  14:00 より前（午前中）もこの状態に含める（ピンは左端）。
- 十両・幕内の内部進捗は塗りで表す:
  - 原則は実績: 「確定済み番数 ÷ その日の総番数」（当日データから算出。
    総番数は日により変わるため固定値を埋め込まない）
  - 実績がまだ無い時間帯は、既存 `boutNumberForWindow` 系の時刻按分で代替。
    実績と推定が食い違う場合は **実績を優先** し、ピンを実績より前に戻さない。
  - 幕下帯は時刻経過のみで塗る。
- ピン（↑）のラベル:
  - デスクトップ: 「イマココ（{東} 対 {西}）」。{東}・{西} は現在の一番の
    対戦カードを当日データから引く（新規のデータ取得は不要）。
  - モバイル: 「イマココ」のみ（四股名はボード本文に大きく出ているため省略）。
  - ラベルが端で見切れる場合は、ピン位置ではなくラベルだけを内側にクランプする。
- 境界時刻（14:00 / 14:15 / 15:45 / 18:00）は、メーターの **最上段** に
  小さく表示する（時刻列 → ラベル列 → バー → ピンラベルの順）。

### D-4: 時刻表示（ボード最上段）

- ボードの最上段右に **現在時刻（JST、HH:MM）＋「現在」** を表示する。
  例: 「16:20 現在」。これは「いま」の根拠を明示し、モバイルで
  四股名を省いた分の情報量を補う。
- 時刻はクライアント表示時に取得し、D-6 の再計算タイミング（60秒）で
  一緒に更新する。SSR 時はサーバー時刻で初期表示し、ハイドレーション後に
  クライアント時刻へ寄せる（既存カードのクリック時再計算と同じ思想）。

### D-5: 状態遷移

| 状態 | メーター | ピンラベル |
|---|---|---|
| 取組未発表 | ボードごと非表示（既存通り） | — |
| 当日・14:00前 | 全セグメント未塗り、ピン左端 | 「本日 14:00 から」相当の案内（ボード側文言に委ねる） |
| 幕下取組中（〜十両開始） | 幕下帯が時刻で進行 | 「イマココ（幕下取組中）」 |
| 十両進行中 | 十両が実績/推定で進行 | 「イマココ（{東} 対 {西}）」 |
| 幕内進行中 | 同上 | 同上 |
| 全取組終了 | 全セグメント塗り切り、ピン右端 | 「本日の取組は終了しました」 |
| 場所の無い日 | ボードごと非表示（既存通り） | — |

- 決定戦が発生した日は、幕内セグメントの総番数が当日データ側で増えるため
  メーターは自動的に追随する（特別扱いしない）。
- 不戦勝・休場で番数が減る場合も、総番数を当日データから取るため追随する。

### D-6: ロジックの置き場所（共有化）と再計算

- 位置計算を `app/lib/live-progress.ts` に切り出す（新規）。
  入力: 当日データ（`TorikumiDailyData`）、JST 現在時刻。
  出力: `{ state, segments: [{key, progress}], current: {division, boutNo, east, west} | null, nowMinutes }`。
- 既存の `nearestTorikumiAnchor` / `boutNumberForWindow` は当面そのまま残し、
  メーター側は新モジュールを使う。両者の「現在の一番」がズレないことは
  テストで担保する。
- 再計算: 初期表示は SSR 値、クライアントでは表示中 60 秒ごとに再計算
  （ポーリングはしない。データ自体はページ再訪・再デプロイで更新される前提）。

### D-7: デザイン言語とアクセシビリティ

- DESIGN.md 準拠: 角 0px、Ink & Gold。セグメントは墨色の面、
  未進行は淡い面、ピンは金。**縦書きは一切使わない**
  （協会ページの体裁は参照しない）。
- ただしこのカードに限り、オーナー指示により **セグメント間にボーダーを
  入れる**（DESIGN.md の No-Line に対する、このコンポーネント限定の例外）。
  ボーダーは細く・淡くし、面の区切りが主・線は従に留める。
- ラベルの格付け: 「幕下取組中」は小さめ＋グレイで目安扱い、
  十両・幕内は通常サイズ、現在の部は太字。これにより視線の主役を
  十両・幕内に置く。
- メーターはボード内テキスト（現在の一番・時刻）の視覚的な重複であるため
  `aria-hidden` とし、スクリーンリーダー向けにはボード側に
  「{HH:MM} 現在、幕内の3番目、{東}対{西}の取組です」相当のテキストを持たせる。
- アニメーションは付けない方針を既定とする（付ける場合は
  `prefers-reduced-motion` で無効化）。
- 新規テキストはすべて `src/locales/ja/common.json` /
  `src/locales/en/common.json` のキー経由（例: `home.imakoko`,
  `home.imakokoMakushita`, `home.imakokoNow`, `home.imakokoFinished` など）。

### D-8: テスト方針

- `live-progress` の単体テスト: 時刻ケース（14:00前 / 幕下帯 / 十両帯 /
  幕内帯 / 18:00以降）と実績ケース（十両全終了済み・幕内半分終了・
  決定戦で番数増）を固定データで検証。
- 既存の `basho-status` 系・ホームのテストが壊れないこと。
- 検証コマンドは従来通り `npm run typecheck` / `npm test` / `npm run build`。

## 5. 実装前の確認事項（残件）

1. 協会公式スケジュールで十一月場所の十両開始・幕内土俵入りの目安時刻を
   確認し、D-2 の定数（14:15 / 15:45）を確定する。
2. ボード最上段の時刻表示の書式（「16:20 現在」で確定か、
   「11/8 16:20」まで含めるか）。既定案: 当日表示が前提のため HH:MM のみ。
