- 作成: 2026-10-28（チャット側 Muse）
- 決定: 2026-10-28、Osada が「初日に間に合わせる（A）」を選択
- 目標: **2026-11-08（十一月場所 初日）までに本番で使える状態**
- 実装担当: ローカル Muse（Wonder）／レビュー・公開後検証: チャット側 Muse
- 前提の調査結果（2026-10-28、main 時点）:
  - お気に入りは `app/lib/my-rikishi.ts` の MyRikishi プロバイダが管理。力士 ID の配列（最大20、`MY_RIKISHI_MAX_COUNT`）、localStorage キー `o-sumo:my-rikishi:v1`、ログイン時は `/api/my-rikishi` と同期・マージ
  - 結果ページ `app/components/TorikumiDayPage.tsx` には既に `matchInvolvesMyRikishi(match, isSaved)` があり、統合結果行には `is-my-rikishi-match` クラスが付く（＝ハイライトの土台は実装済み）。**不足しているのは「絞り込みトグル」そのもの**

## 目的

速報を見に来るユーザーが、十両・幕内の全取組から推しの取組だけを即座に見つけられるようにする。My Rikishi 登録 → 結果ページで推しだけ表示、という再訪ループの要。

## 決定事項

### F-1 スコープ（初日リリース）
- 対象は取組日ページの **結果表示（mode='result'、統合結果行）** を第一とする
- 予定表示（mode='schedule'、TorikumiTable 側）は、同じヘルパーで低コストに適用できる場合のみ同一 PR に含める。難しければ初日後のフォローアップに分離してよい

### F-2 データソース（重要：本番公開に依存しない）
- 絞り込み判定は既存の MyRikishi プロバイダ（`isSaved(id)`）を使う。新規のデータ取得・API は追加しない
- これにより **未ログイン（この端末の localStorage のみ）でもフィルターは動作する**。My Rikishi 本番公開（同期）は「別端末でも同じ推しが出る」という上乗せであり、本機能の前提条件ではない。両トラックは独立に進めてよい

### F-3 トグルの仕様
- 結果ページ上部（TorikumiDayBar 近傍）にトグル「推しだけ表示」を置く
- ON のとき、十両・幕内両セクションで推しが関わる取組だけを表示する。部の区切り行（division-divider）は残し、件数は表示中の件数に合わせる（表記は i18n キーで「推しのみ表示中」等を併記してよい）
- 推しの休場行（absent）は非表示にせず残す（既に `is-my-rikishi-match` が付く行である）
- トグルの ON/OFF は端末に保持する（localStorage に新規キー。既存の命名規則に合わせる）。デフォルトは OFF

### F-4 空状態
- お気に入り未登録（0件）のとき: トグルは出さない、または無効化した上で「推しを登録すると絞り込めます」＋ My Rikishi ページへの導線を表示する（文言は i18n キー）
- 登録はあるが本日の取組に推しが1人もいないとき: 「本日の取組に推しはいません」相当の表示と、全件表示に戻す導線を出す。空ページで終わらせない

### F-5 ハイライト
- 既存クラス `is-my-rikishi-match` の CSS が現状どう効いているか確認する。視認が弱い場合は Digital Washi の範囲で強める（金の淡い背景／金の下線など、過剰にしない）。トグル OFF でもハイライト自体は現行どおり効くこと

### F-6 i18n
- 新規文言はすべて `src/locales/{ja,en}/common.json` のキーで追加する（`torikumi.day.*` 配下を想定）。ハードコード禁止

### F-7 テスト
- 絞り込みは純粋関数として切り出して単体テストする（例: セクション配列＋ isSaved → 絞り込み済みセクション。休場行の扱い・両部またぎ・0件ケースを含む）
- トグルの表示条件（未登録時）・空状態の分岐にコンポーネントテストを付ける
- 既存テスト一式が緑であること

## やらないこと

- My Rikishi の登録フロー・上限（20）の変更
- フィルター条件の追加（部屋別・番付別など）。今回は「推しかどうか」のみ
- イマココメーターとの結合（別コンポーネント・別 PR）

## 受け入れ条件

1. 結果ページでトグル ON → 推しの取組だけが両部を通じて残り、区切り行の件数が一致する
2. 未ログイン・ローカルお気に入りのみの状態でも動作する
3. お気に入り0件／本日推しなしの両ケースで行き止まりにならない
4. トグル状態が再訪時に保持される
5. test / typecheck / build が緑
