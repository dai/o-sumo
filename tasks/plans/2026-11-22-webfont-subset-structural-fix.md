# o-sumo webfont サブセット構造対策 指示書

作成：2026-11-22（下書き）、2026-11-23 に本ブランチへ push。根拠は tracked item
「o-sumo webfont subset structural fix」の GOAL.md。サイズ実測表は TBD のまま渡す：
実測はローカル側の最初のタスク（第1層）として実施し、結果を PR に反映すること。

## 背景

- webfont はサブセット方式。ソース／データに出る文字が coverage に無いと
  `app/webfont.test.ts` が失敗する。
- 文字の出どころは3系統：(a) UI文言、(b) 力士・行司・呼出などの名前データ、
  (c) データ更新で入る記事・訃報等の文字。
- 再生成（`npm run fonts:subset`、`scripts/fonts/build_webfonts.py`）は手作業で、
  データ更新（update_sumo_data.py）や実装手順に組み込まれていない。
  だから毎回「テストで初めて気づく」。
- 実害：main 自体が落ちた状態になると、無関係なPR（Dependabot等）まで
  全部同じ失敗で止まる。2026-11-16 は #761〜#763 がこれで止まり、
  先に修正PR #764 が必要だった。

## やること（3層）

### 1. サイズ実測（最初にやる。判断の前提）

- 現在のサブセット（5ウェイト合計と各ファイル）のサイズを測る。
- カバレッジを広げた場合のサイズ増を試算する：候補は常用漢字（2,136字）＋
  人名用漢字＋四股名・行司・呼出辞書の全使用文字。
- 増分が小さければ拡張を採用。大きい場合は第2層（自動化）を主軸にし、拡張範囲を絞る。

### 2. 再生成の手順組み込み（本命）

- データ更新の流れの最後に webfont チェックを入れ、不足があれば再生成までを
  同じPR／同じ更新に含める。「main が落ちている」状態を作らない。
- UI文言を足す実装でも、完了条件に webfont テスト通過（不足時は再生成を含む）を
  含める運用にする。今回 v2 でローカルが実施した scratch 事前チェックの正式化も候補。
- CI 側の自動再生成・自動コミットは、仕組みが重くなるなら無理に入れない。
  まず手順組み込みで足りるか判断する。

### 3. カバレッジ拡張（不足自体を減らす）

- シード文字集合に、常用漢字＋人名用漢字＋辞書系データの全文字を加える。
- 対象外の手として、珍しい文字のシステムフォント・フォールバックは書体が混ざり
  見た目が揺れるため本命にしない（2026-11-20 チャット側見解、Osada 未裁定。
  採用する場合は理由を付けて再提案）。

## 完了条件

- `npm run fonts:subset` の再生成手順と webfont テストが main で通る状態。
- データ更新・実装のどちらの流れでも、不足文字が出たら同じPR内で再生成まで含む運用になっている。
- フォント差分が想定範囲で、無関係な生成差分が混ざっていないこと（PRレビューで確認）。
- カバレッジ拡張を採用した場合は、そのサイズ増分を PR 概要に明記すること。
