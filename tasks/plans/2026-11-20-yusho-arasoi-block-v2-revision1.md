## 1. 首位グループ表から「最大」列を削る

- 首位グループ表の列は **差・力士・成績・残り・その日の相手** の5列にする。
- 「最大」（maxPossibleWins の成績表示）は表示から外す。lib 内の maxPossibleWins の計算自体は優勝条件の判定で使うため残す。
- 未使用になる locale キー（contTableMax 等）があれば掃除する。

## 2. 優勝条件表の「全勝時」列を「勝ち/負け」列に変える

考え方（Osada）: 残り全勝の話は表の下の条件文だけで十分。表では「当日が終わったらどうなるか」を見せる。

- 列名: ja「勝ち/負け」 / en「Win/Lose」
- セルの中身は、その力士の **対象日（ページの日）の取組** をシミュレーションした成績:
  - 勝った場合の成績 / 負けた場合の成績 を `12勝1敗/11勝2敗` の形で1セルに並べる（先が勝ちケース）。
  - 対象日の取組が未確定の力士だけこの形にする。
  - 対象日の取組が確定済みの力士（過去日のページ、または当日に自分の取組が終わっている力士）は「—」。
  - 対象日に取組がない力士（休場など）も「—」。相手の休場による不戦勝は確定扱い（データ上で勝者が付いているものは確定済みとして扱う）。
- lib に当日シミュレーション（例: `todaySimulation: { win: {wins, losses}, lose: {wins, losses} } | null`）を持たせ、component はそれを表示するだけにする。既存の hasPendingBoutToday の判定をそのまま使う。
- **条件文（表の下の文章）は変更しない。** 「残り全勝で…」等の全勝ベースの文言は従来どおり残す。
